你要把一套「AI API 中转站 + 生图站」部署到一台新的 Linux VPS 上（境外，最低 2 核 4 GB）。

【第一步：拿到代码和大文件】
仓库是私有的，owner 会给你一个只读令牌（就是一串 github_pat_ 开头的字符）。

  export GH_TOKEN=<owner 给你的只读令牌>

  # 方式 A（有 gh CLI，推荐）
  gh repo clone __GITHUB_OWNER__/__GITHUB_REPO__ /root/mssk-handover

  # 方式 B（没有 gh CLI）
  git clone https://oauth2:$GH_TOKEN@github.com/__GITHUB_OWNER__/__GITHUB_REPO__.git /root/mssk-handover
  git -C /root/mssk-handover remote set-url origin https://github.com/__GITHUB_OWNER__/__GITHUB_REPO__.git   # 清掉令牌痕迹

  cd /root/mssk-handover
  bash scripts/fetch-assets.sh        # 拉 4 个大文件（约 121 MB）并校验 sha256

  看到 ALL ASSETS OK 才继续。

【第二步：读两页，别读多】
  README-FIRST.md    —— 这套系统是什么、有哪些硬约束
  07-MIGRATION.md    —— 执行主线：阶段 A → B1…B8 → C

【第三步：执行】
  按 07-MIGRATION.md 走，每个 CHECKPOINT 停下来，把该步要求的结果发给 owner，等他确认再继续。

【四条硬约束，违反会出事故】
  1. 不要在新机器上编译任何前端代码（产物已在 console.tar.gz 里，解包即用）
  2. 不要改 new-api 镜像版本（冻结在 v1.0.0-rc.51），不要启用自动升级
  3. /v1 必须经过 relay-keepalive(3002) 再到 new-api(3001)，不能直连 3001
  4. 数据库必须 one-api.db 与 one-api.db-wal 成对替换，只换 db 会丢最近写入

【需要 owner 配合的四件事（在 00-YOU-DO-THIS.md，可直接转给他）】
  新机 IP+SSH、放行 22/80/443、两个域名 + A 记录、05-SECRETS.enc 的解密口令
  域名不会配 → 把 02-CONFIG/caddy/DOMAIN-AND-TLS-GUIDE.md 发给他，里面有点击级步骤

遇到输出与文档不一致就停下来问 owner，不要自己试别的办法。

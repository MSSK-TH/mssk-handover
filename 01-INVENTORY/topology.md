# 01-1 · 部署形态与数据来源

## 目标形态：单机全栈

```
                       ┌──────────────────────────────────┐
   api.example.com     │  新机器（境外，2 核 4 GB 起）        │
   image.example.com   │  caddy  :80/:443                 │
        │              │   ├─ /v1/*    → keepalive:3002    │
        └────────────► │   │              → new-api:3001   │
                       │   ├─ /api/*   → new-api:3001      │
                       │   ├─ /static/*, 其余 → console    │
                       │   └─ image 域名 → image-web:8788   │
                       │                                  │
                       │  imagegen-shim :8899（仅本机）     │
                       │  cron: quota / disk-guard         │
                       └──────────────────────────────────┘
```

**没有第二台机器、没有跨机同步、没有跨机代理。** 所有组件同机，互相通过 `127.0.0.1` 通信。

## 数据来源（旧部署）

`04-DATA/` 与 `05-SECRETS.enc` 里的东西来自旧部署，迁移完即与新机无关：

| 数据 | 来源 | 说明 |
|---|---|---|
| `one-api.db` + `-wal` | 旧部署的 new-api 数据目录 | 所有业务数据（用户/令牌/渠道/日志聚合） |
| `one-api.db.backup-latest` | 同上 | 迁移时刻的备份，出问题用它恢复 |
| 网页版 Cookie（`shim-cookies/`） | 旧部署的 imagegen-shim | 生图网页版模式的登录态，换 IP 后可能失效 |
| 控制台静态产物 | 旧部署的 console 目录 | 已构建好的前端，直接铺进 `/opt/mssk/console` |

> 旧部署当时怎么分的机器、为什么分，对本次部署没有影响——
> 包里的配置已经是单机版本，照 `07-MIGRATION.md` 做即可。

## 关于旧部署的两点提醒

1. **不要照旧资料再搭第二台**。`01-INVENTORY/` 里列出的容器与端口是**新机要跑的那些**，
   不是"两台机器各跑一半"。
2. **旧机器在验收通过 24 小时内不要关**。它的作用是：万一新机有问题，把 DNS 改回去即可恢复服务。
